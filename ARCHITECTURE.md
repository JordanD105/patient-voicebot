# Architecture

The caller is a LiveKit Agents worker in pipeline mode. A call is a room with two audio participants: this process, which speaks as the patient, and a SIP participant, which is the clinic. The worker never greets first. It starts the session so the models are warm, keeps the microphone off, dials, and only then listens. Ringback would otherwise get transcribed as a person.

Speech-to-text is Deepgram Nova-3, the language model is OpenAI gpt-4.1-mini, and speech synthesis is Cartesia Sonic-3. By default those three are reached through LiveKit Inference, so the audio path and the model path share one network. That is still a cascaded pipeline: text crosses each boundary, and a speech-to-speech realtime model is not in the loop. Inference won because a laptop otherwise opens three vendor sockets per turn, and the extra setup was more likely to sink the submission than a different STT brand. `PIPELINE=direct` swaps in the Deepgram, OpenAI, and Cartesia plugins with your own keys when Inference is off. AssemblyAI and ElevenLabs were the other serious options. AssemblyAI is strong on messy audio and slower to endpoint. ElevenLabs sounds excellent and adds noticeable time-to-first-audio on a phone turn. Nova-3 plus Sonic-3 is the low-latency pair, and gpt-4.1-mini is obedient enough to stay in a short patient persona without the cost of a larger model.

Turn taking uses the bundled local Silero VAD, loaded in the process prewarm so the first call does not pay the model load. Endpointing waits 0.65 seconds after speech stops, and at most 2.4 seconds, so a receptionist can pause inside a slot offer without the patient cutting in. The reply starts only after that turn commits. Starting the LLM while the clinic is still being transcribed lets their own final transcript cancel the reply, which leaves the caller silent. Interruptions need about half a second and two words. A false barge-in does not resume, for the same reason: the resume path was cancelling the answer. If a clinic turn still produces no patient audio, a watchdog asks the model to answer that turn. Echo warmup is forced to zero because this is a phone leg, not a laptop speaker. One scenario deliberately talks over the clinic at 14 seconds, using `session.say`, so that case is a choice rather than a turn-detector accident.

The phone network is an outbound SIP trunk already configured on the LiveKit project. The dialer creates an agent dispatch whose metadata carries the scenario id. The worker reads that metadata and creates the SIP participant itself, with `wait_until_answered`, and locks the session onto that participant so it does not hear its own voice. The destination is a constant. Both the dialer and the worker reject anything else, and the CLI has no phone-number argument. One `SIP_CALLER_NUMBER` is sent as the outbound caller ID on every call.

The recording is the SDK's stereo Ogg/Opus file, copied out of the job directory when the session closes. Left is the clinic audio going into the pipeline. Right is the patient audio coming out of TTS. Egress to object storage would have added a bucket and a second clock; the in-process recorder is already aligned to the same turns as the transcript. The transcript is written from `conversation_item_added` as the call happens, so a failed hangup still leaves text on disk. A watchdog speaks a goodbye at the scenario cap and deletes the room, which drops the SIP leg.

Noise cancellation on the inbound phone audio is optional (`BVCTelephony` when the plugin loads). It helps Nova-3 on 8 kHz audio and is the first thing to turn off if a session fails at startup. Keyterms for drug names and the clinic vocabulary are passed into STT so those words survive a phone codec.
